Experimental features — what the master toggle hides

One master gate, Experimental features (GeneralSettings.experimentalFeaturesEnabled, prefs key experimental_features, default false), switches nine UI surfaces on or off across three feature clusters: on-device models, AI Knowledge / RAG, and Local Semantic Search.

Overview

When the gate is off (the default), the nine surfaces below are hidden — nothing is deleted. Installed on-device model files stay under <filesDir>/, knowledge bases stay on disk, and any KB already attached to a chat or report keeps sending its context at API time — only the entry-point UI disappears. Flipping the toggle back on reveals everything intact.

This is a real per-call-site if (experimentalFeatures) gate in the Compose tree — not a Kotlin @OptIn(Experimental…Api) annotation, which is unrelated and appears nowhere in this doc.

Source of truth is the field's own doc comment in viewmodel/AppViewModelTypes.kt:

“Master gate for experimental / advanced surfaces. When false, hides every UI surface related to on-device models (Local LLMs, LiteRT embedders, the synthetic AppService.LOCAL provider), AI Knowledge / RAG (Hub card, attach buttons in chat + report, share-target ‘Add to Knowledge’ entry, Knowledge screens), and Local Semantic Search. Installed model files on disk stay put; flipping this back on reveals everything intact. KBs already attached to existing chats / reports keep sending context at API time even while the attach UI is hidden.”

Where the toggle lives

Settings → UI tweaks → “Experimental features”. The UI-tweaks sub-screen is reached from the Settings landing card subtitled “Model name layout, full-screen, ladybug icons, experimental features.” The toggle's own in-screen description reads:

“Master gate for on-device Local LLMs, LiteRT embedders, AI Knowledge / RAG, and Local Semantic Search. Off (default) hides those UI surfaces — installed model files and KBs stay on disk, and any KB already attached to a chat or report keeps sending context at API time.”

Immediately below it, inside an if (experimentalFeatures) block, sits a second toggle — “Show Knowledge card on home page” (surface #4) — so it only appears once the master gate is on.

On-device models (Local LLMs + LiteRT embedders)

1 · AI Setup → AI Models → “Local Models” card

The entry to the on-device LLM + LiteRT text-embedder setup screen (install / manage .task and .tflite models; subtitle “On-device LLMs and LiteRT text embedders”, route AI_LOCAL_MODELS_SETUP). Gated by an if (experimentalFeatures) block inside ModelsSetupScreen.

ui/settings/SetupScreens.kt:193

2 · Chats hub → Local LLM chat card

The dropdown card that picks an installed on-device LLM and jumps straight into a local chat session. Gate is experimentalFeatures && installedLocalLlms.isNotEmpty() — shown only when at least one .task LLM is installed.

ui/chat/ChatHub.kt:122

3 · Model pickers → synthetic LOCAL provider + local models

The on-device models (and the synthetic AppService.LOCAL provider, id "Local") stay invisible in every model picker even when .task / .tflite files exist on disk. Unlike the other eight surfaces (which receive the flag as a parameter), this picker reads the prefs flag directly:

context.getSharedPreferences("eval_prefs", MODE_PRIVATE)
    .getBoolean("experimental_features", false)

…so it doesn't have to thread the flag through every caller. When off, localModelsForFilter is emptyList(), so AppService.LOCAL is never appended to the service list.

ui/other/Selection.kt:246-261

See local-runtime for the LocalLlm / LocalEmbedder runtime these three surfaces gate.

AI Knowledge / RAG

4 · Settings → UI tweaks → “Show Knowledge card” toggle

The secondary toggle itself is hidden (it only makes sense once Knowledge is enabled), inside an if (experimentalFeatures) block directly below the master toggle in the UI-tweaks screen. The showKnowledgeCard field it controls additionally gates surface #5.

ui/settings/SettingsScreen.kt:1614

5 · Hub → “AI Knowledge” card

The home-screen entry into the Knowledge / RAG screens. Requires both experimentalFeaturesEnabled and showKnowledgeCard:

if (generalSettings.experimentalFeaturesEnabled
    && generalSettings.showKnowledgeCard) { … }

ui/hub/HubScreens.kt:153

6 · Chat composer → “Knowledge” attach chip

The per-chat KB attach chip (multi-select over saved KBs). Gate is:

(experimentalFeatures && availableKbs.isNotEmpty())
    || attachedKnowledgeBaseIds.isNotEmpty()

…so it shows when the gate is on and a KB exists, and also (gate off or on) whenever a KB is already attached to this chat, rendering the attached count so the user can still see / edit the attachment.

ui/chat/ChatScreens.kt:817

7 · New Report → “Attach knowledge” button

The report-start KB attach button (multi-select over saved KBs). Gate is experimentalFeatures && allKbs.isNotEmpty() — shown only when at least one KB exists.

ui/report/start/SelectionPhase.kt:205

8 · Share-target chooser → “Add to Knowledge” card

The ACTION_SEND landing card that opens the Knowledge screen with the shared file / URL pre-staged. Plain shared text that isn't a URL can't be ingested here and is steered to New Report instead.

ui/share/ShareChooserScreen.kt:104

See knowledge for the RAG subsystem these five surfaces gate, and share-target for the chooser context around surface #8.

Local Semantic Search

9 · Search AI Reports → “Local semantic search” item

The on-device (embedder-backed) semantic search over reports. The other three search modes — Quick local search, Extended local search, Remote semantic search — stay visible regardless of the gate; only this on-device item sits behind if (experimentalFeatures).

ui/hub/SearchAiReportsScreen.kt:63

What is not affected

Installed on-device model files
Under <filesDir>/local_llms/ and <filesDir>/local_models/ — untouched, and also excluded from backup (see backup-restore).
Knowledge bases on disk
KBs, sources, and embeddings persist regardless of the gate.
KBs already attached to a chat or report
They keep injecting context at API time even with the gate off. In chat the Knowledge chip even stays visible (showing the attached count) so you can still edit / remove the attachment (surface #6's OR clause); in New Report the attach button is hidden, but the already-attached KB still rides along on the report and injects at dispatch time.
Remote & the two local text search modes
Always visible; only Local semantic search (surface #9) is gated.

Storage & round-trip

The flag lives on GeneralSettings, persists to the main eval_prefs SharedPreferences store under key experimental_features, and round-trips through Import/Export (serialized as experimentalFeaturesEnabled in ui/settings/ImportExportScreen.kt:362,483) and the full backup zip.

Help: the toggle's own help card lives under the Settings-admin “UI tweaks” topic (helpTopic = "settings_ui") — see help.
