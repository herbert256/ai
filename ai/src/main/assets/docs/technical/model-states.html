Model states & type overrides

Five parallel lists, all keyed on the "providerId:model" pair (same shape as ReportModel.deduplicationKey), decide whether a (provider, model) tuple is benched, blocked, skipped by the test sweep, marked unreachable, or has its API type forced by hand. Four are advisory/exclusion lists; the fifth (manual type overrides) is a classification list.

Overview

Each list has its own CRUD screen under AI Setup → AI Models (the ModelsSetupScreen cards). The four Settings.*-backed lists are plain fields on the settings object and round-trip through Import/Export; cooldowns are a separate runtime store (ModelCooldownStore) with its own SharedPreferences file.

Auto: sweep FAIL → block, PASS → un-block. Picker: dim + 🚫 caption. CRUD at cruds/models/blocked/.

The CRUD screens are reached through the two-tier SettingsSubScreen router: AI Setup → AI Models lands on AI_MODELS_SETUP, whose cards push AI_BLOCKED_MODELS / AI_TEST_EXCLUDED_MODELS / AI_INACCESSIBLE_MODELS / AI_MANUAL_MODEL_TYPES / AI_MODEL_COOLDOWNS. Each is a four-file CRUD (add / edit / list / view).

The three advisory states — cooldown, blocked, inaccessible — collapse into one per-row lookup, ModelAdvisoryState (ui/shared/ModelAdvisory.kt), hoisted once per picker via rememberModelAdvisoryLookup. It combines ModelCooldownStore.cooldowns (a live StateFlow) with Settings.blockedReasonByKey and Settings.inaccessibleReasonByKey, so each row pays only an O(1) map lookup. A model can be in zero, one, two, or all three states independently. The dim treatment is identical everywhere: row alpha 0.4f when any state is active, a leading badge (⏳ / 🚫 / 🔒) via ModelAdvisoryBadges, and a one-line reason caption via ModelAdvisoryCaptions — but the row stays clickable so the user can still pick it deliberately. A cooldown's benchedUntil is additionally filtered to > System.currentTimeMillis() inside stateFor, so an expired bench never dims a row even before the store prunes it.

Test-excluded has no picker effect at all — it only gates the "Test all models" sweep — and manual type overrides aren't an advisory state either; they change how a model classifies, not whether it's dimmed.

Cooldowns

Transient, time-based benches — the only one of the five lists not stored on Settings. A 429 gets the pair benched (until a computed availableAtMs) in any of four cases the retry interceptor recognises:

Google quota exhausted
Per-day quota response; benched until the next Pacific midnight (or the retry-after hint if present).
Cohere trial-key monthly cap
Trial keys hit a long per-month cap; benched until next month start.
Billing / spending-limit 429
Provider out of credits or over its spending limit — benched 6 h.
Long Retry-After ≥ 1 h
The generic catch — any 429 whose hint exceeds LONG_RETRY_THRESHOLD_MS (60×60×1000 ms) benches the model regardless of source.

See throttle for the full 429 retry path that fires these, and for the separate short-bench tier (markShortBench) that type-A fixed-model batches (Fan-out, Judge the judges, Rank the translators) use instead — that one is session-only, not persisted, and doesn't touch this store's cooldownMap.

Storage

A plain object singleton (data/ModelCooldownStore.kt) — both the OkHttp 429 interceptor (no Context) and the Compose pickers read it — with its own SharedPreferences file (/data/data/com.ai/shared_prefs/model_cooldowns.xml):

map
Map<String, Long>, key map
"providerId:model" → epoch-ms expiry.
traces
Map<String, String>, key traces
"providerId:model" → the API-trace filename whose 429 caused the bench. Device-local — not carried in Import/Export or in the public cooldowns StateFlow.

Reads are side-effect-free (Bug 48): isUnavailable and availableAt are pure timestamp compares (until > now) that don't drop the expired entry — model pickers call them per row, so they must not write SharedPreferences or emit on the StateFlow as a side effect of a "read". Actual pruning (delete + persist) happens only in init (on load) and the pruneExpired sweep.

Public surface 
object ModelCooldownStore {
    val cooldowns: StateFlow<Map<String, Long>>

    fun init(context: Context)
    fun markUnavailable(providerId, model, availableAtMs, traceFile?)
    fun isUnavailable(providerId, model): Boolean
    fun availableAt(providerId, model): Long?
    fun remove(providerId, model)
    fun clearAll()
    fun entries(): List<CooldownEntry>
    fun importMerge(incoming: Map<String, Long>)
    fun cooldownCaption(untilMs: Long): String
}

entries() is raw, not expiry-pruned, so the CRUD list can show and clear stale rows by hand. cooldownCaption returns "rate-limited · back 14:30" for entries expiring today, or "rate-limited · back May 15 14:30" otherwise (Bug 47 compares day-of-year and year, so a cooldown exactly one year out on the same day-of-year doesn't render as today's time).

Picker & engine effect

Every model picker (per-provider list, +Agent, +Model, the secondary picker, Fan-out / Fan-out icons launch screens, the Model Info "in AI config" card) dims the benched row with the cooldownCaption string; the tap target stays live so the user can override deliberately. FanOutEngine, the Fan Meta batch, ModelTestEngine, and the per-agent report-icon chain consult isUnavailable before committing a pair to the run — benched pairs are skipped or shifted to ERROR with a reason.

CRUD

AI Setup → AI Models → Model cooldowns lists every stored cooldown (expired and live), grouped by provider, each row showing model, expiry, and a 🐛 button that deep-links into the captured trace.

  • Remove — drop one entry (un-bench).
  • Clear all — drop every entry.
  • Tap a row → the API trace screen for the 429 that caused it.

The store is part of Export & Import → Runtime data and the full backup zip; imports merge via importMerge (trace filenames don't travel).

Blocked models

Manually flagged pairs the app treats as failing. Identity is the (providerId, model) pair — no UUID — with an optional reason (default "").

BlockedModel

model/SettingsModels.kt

providerId: String, model: String, reason: String = "". key is "$providerId:$model".

Populated by
The "Test all models" sweep, per item, live as the run progresses — AppViewModel.applyTestItemIncrement fires on each PASS/FAIL transition: PASS drops the key from Blocked; FAIL not on cooldown upserts it with the error (take(300), default "Test failed"); FAIL on cooldown drops it (the cooldown list owns that pair). Writes are in-memory only; the engine flushes once at end-of-run / cancel. Also hand-curable via the CRUD (upsertBlockedModel / removeBlockedModel).
Picker effect
Dimmed in every picker with a red "🚫 Blocked: …" caption (blockedReasonByKey feeds the advisory lookup).
Stored
Settings.blockedModels, prefs key ai_blocked_models.

Test-excluded models

A pure skip-set for the "Test all models" sweep — no reason field, no UUID; a simple "providerId:model" set.

TestExcludedModel

model/SettingsModels.kt

providerId: String, model: String. key is "$providerId:$model".

Populated by
Auto-added when a probe's cost exceeds the 5¢ ceiling (COSTLY_PROBE_USD_THRESHOLD = 0.05) — the same per-item applyTestItemIncrement hook appends the model (no-clobber) when item.totalCost > COSTLY_PROBE_USD_THRESHOLD, in memory, flushed at end-of-run, so the next sweep won't pay for it again. Also seeded from assets/excluded.json on app start (TestExcludedSeed.ensureAllPresent), a delta-merge that never touches existing keys. Hand-curable via the CRUD.
Picker effect
None — these models stay fully visible and selectable everywhere; the list only gates ModelTestEngine.startRun (via isTestExcluded).
Stored
Settings.testExcludedModels, prefs key ai_test_excluded_models.

Inaccessible models

Pairs genuinely unreachable on the user's account/tier (e.g. Together or OpenRouter non-serverless catalog entries). Carries a required reason.

InaccessibleModel

model/SettingsModels.kt

providerId: String, model: String, reason: String (required). key is "$providerId:$model".

Populated by
The test engine when a probe's error matches a tier-gating signal — non-serverless (Together dedicated-only entries), is not available on (SambaNova's HTTP 410 wording), or a bare HTTP 404 (model id not found anywhere reachable on this account). upsertInaccessibleModel records it (reason take(200)) and the item is marked PASS (kept in the run so Total stays stable) rather than counted as FAIL. Also seeded from assets/inaccessible.json on start (InaccessibleSeed.ensureAllPresent); blank-reason seed rows default to "Unable to access non-serverless (bundled)". Hand-curable via the CRUD.
Picker effect
Dimmed with a tertiary "🔒 Inaccessible: …" caption (inaccessibleReasonByKey). Inaccessible rows dim and stay selectable like the other two advisory states — they used to hide from the secondary picker but no longer do.
Stored
Settings.inaccessibleModels, prefs key ai_inaccessible_models.

Manual model-type overrides

Per-model API-type assignments that win over autodetection — a flat, cross-provider CRUD list living at the Settings root (one entry per override, identified by UUID id), rather than one map per provider.

ModelTypeOverride

model/SettingsModels.kt

id: String, providerId: String, modelId: String, type: String, plus three optional capability flags: supportsVision 👁, supportsWebSearch 🌐, supportsReasoning 🧠 (all default false).

type is one of the ten tokens in ModelType.ALL — chat, responses, embedding, rerank, image, tts, stt, moderation, classify, ocr. Note ModelType is a Kotlin object of const Strings, not an enum.

Type & capability precedence

Type (Settings.getModelType): a matching override returns first and short-circuits everything — ahead of the LiteLLM type (PricingCache.liteLLMModelType, used only when it's not plain CHAT), the per-provider modelTypes map (native list-API metadata), and the ModelType.infer naming heuristic.

Capability (isVisionCapable / isWebSearchCapable / isReasoningCapable): checked in order — the per-provider set (e.g. ProviderConfig.visionModels, populated by Model Info edits and fetch unions) → the matching override flag → the per-provider precomputed cache (visionCapableComputed etc., refreshed by recomputeCapabilities) → a slow layered lookup (provider /models self-report → LiteLLM flag → models.dev → further catalog flags where the capability has them — Requesty / llm-stats / TrueFoundry / CloudPrice, coverage varies per capability → ModelType.infer* naming heuristic). An override flag can only add a capability — because each lookup returns true early on a positive match, it never clears one already implied by the per-provider set or the catalog. This is how a user forces a model the catalog mis-classifies (e.g. a vision/web-search/reasoning model the autodetect missed).

The edit form pulls the provider's known models from aiSettings.getProvider(…).models; if the provider hasn't been fetched yet the model dropdown is empty and prompts a fetch first.

Stored in Settings.modelTypeOverrides, prefs key ai_model_type_overrides.

The four ai_* keys live in the main eval_prefs settings store. The three exclusion lists (ai_blocked_models / ai_test_excluded_models / ai_inaccessible_models) are each written null when empty (so the key disappears); ai_model_type_overrides is written unconditionally as a JSON array. All four round-trip through Import/Export. The model_cooldowns store is its own SharedPreferences file and is not in this set — its traces sidecar stays device-local even though the cooldown map itself is backed up.
