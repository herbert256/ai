Test all models

End-to-end probe of every configured model in every active provider, in parallel, with a type-appropriate fixed prompt and per-(provider, model) trace capture. Surfaces under Housekeeping → Test → Test all models and feeds the Blocked / Test-excluded / Inaccessible lists under AI Setup → AI Models. No doc/*.md file covers this subsystem yet — this page is verified directly against viewmodel/ModelTestEngine.kt and the ui/other/ModelTest*.kt screens.

Engine

ModelTestEngine owns the single run. It exposes two StateFlows:

run
StateFlow<ModelTestRunState?>
The latest run snapshot — drives every L1 / L2 / L3 screen.
throttledKeys
StateFlow<Set<String>>
Live set of (provider, model) keys currently parked on the per-host gate — drives the L1 "Throttled" stat.

hydrate(context) loads the persisted run on first screen entry (a no-op once the flow already holds one). Pre-snapshot runs whose bucket counts don't reconcile against catalogTotal are backfilled from the live Settings + provider catalogs and re-saved, so an older persisted run still renders a correct L1 top row.

Catalog partition

A run is built from the user's provider selection. startRun partitions every model of every selected provider into four buckets that always sum to catalogTotal by construction (the stats panel reconciles without rounding errors):

For testing
Probed in the run. Reported as Done / Error / Bench / Throttled.
Inaccessible
In Settings.inaccessibleModels (user-curated + seeded from assets/inaccessible.json). Dropped from the sweep entirely; counted in inaccessibleAtStart.
Test-excluded
In Settings.testExcludedModels (probe cost > 5¢ auto-rule + manual + seeded from assets/excluded.json). Skipped; counted in excludedAtStart.
No chat
Model type is in ModelType.NON_TESTABLE_TYPES — IMAGE, TTS, STT, CLASSIFY, OCR. Dropped; counted in noChatAtStart.

Only active providers with a non-blank API key are candidates (testableProviders(), used by the Select screen). Active providers with zero models after filtering never appear in the run.

Probe types

The probe called per item depends on the model's resolved ModelType — not everything gets the same chat probe:

CHAT / RESPONSES / UNKNOWN / null
probeChat — the classic "Reply with exactly: OK" prompt, capped at AnalysisRepository.TEST_MAX_TOKENS (64) output tokens so balance-gating providers don't pre-auth the model's whole output window. Counts as reachable even on HTTP 200 + empty visible content, as long as the response burned output or reasoning tokens (gpt-5/o-series via OpenRouter with encrypted reasoning details; Gemini 2.5/3.x thinking budgets) — the probe's job is reachability, not "did it produce visible text".
EMBEDDING
probeEmbedding — one short string through embedWithStatus (the status-returning sibling of the silent embed() RAG/Knowledge use). PASS = a vector came back; response text shows its dimension count.
RERANK
probeRerank — a trivial (query, one document) pair through callRerankApi. Providers without nativeRerankUrl configured fail with an explanatory message.
MODERATION
probeModeration — one innocuous input through callModerationApi. PASS = a parseable result; flagged or not is irrelevant, the API just has to answer. Providers without nativeModerationUrl fail the same way as rerank.

All four funnel into the same internal ProbeResult shape (success flag, error message, response text, duration, token usage) so runOne applies the outcome uniformly regardless of which probe ran.

Run lifecycle

Each item runs with the provider's default agent config, wrapped in a 60 s withTimeout (a stuck free-tier worker would otherwise pin its per-host slot for the full ~120 s read timeout and block every sibling queued behind it) and ProviderThrottle.suppressInlineRetry — a 429/529 here is recorded as a result, not slept-and-retried in place, so it can't pin an ioCap permit for tens of seconds.

  • PENDING 🕓
    • permit acquired
      • RUNNING ⏳
        • timeout (60 s) → FAIL, "Test timed out after 60s"
        • tier-gated error (non-serverless / "is not available on" / HTTP 404) → PASS, moved to Inaccessible
        • reachable response → PASS ✅
        • other error → FAIL ❌

Tier-gating detection treats three error shapes as "not really a failure, just not reachable on this account": Together's "non-serverless" wording, SambaNova's "is not available on" (HTTP 410), and a bare HTTP 404 from any provider (endpoint/model id not found). These items are recorded PASS with response text "Inaccessible — tier-gated, will be skipped next sweep" and upserted into Settings.inaccessibleModels — kept in _run.items so the run's Total stays stable rather than disappearing mid-sweep.

A genuine PASS clears any stale >1h-429 cooldown (ModelCooldownStore.remove) so a model that recovers isn't gratuitously dimmed elsewhere. Independently, the shared 429 retry path can bench a model for the rest of the run: any provider whose Retry-After hint exceeds LONG_RETRY_THRESHOLD_MS (1 hour), a Gemini daily-quota hit, a Cohere trial monthly cap, or a billing/credits 429 all call ModelCooldownStore.markUnavailable(providerId, model, availableAtMs, trace) — the pair then shows benched in L1's "Bench" stat and in the Model cooldowns picker. See Model states — Cooldowns.

State is persisted to <filesDir>/test_run.json (single document via ModelTestRunStore, same lock+atomic-write shape as ChatHistoryManager) after every item completion and once more on run end — a process kill mid-sweep doesn't lose progress. Live per-item Blocked / Test-excluded updates happen in memory as each item transitions (AppViewModel.applyTestItemIncrement); the settings snapshot is flushed to disk once at end-of-run / cancel, not per item.

Resume / rerun / cancel outcomes

Check current test run (resumeRun) — re-dispatches a run whose coroutine died (process kill, crash) but still has PENDING/RUNNING items; RUNNING items with no live worker reset to PENDING first. Returns NO_RUN / ALREADY_RUNNING / ALREADY_COMPLETE / RESUMED, each surfaced as a toast.

Rerun Errors (N) (rerunErrors) — flips every FAIL item back to PENDING and re-dispatches just that subset; PASS items are untouched. Also permanently drops FAIL items that wouldn't belong in a fresh sweep any more (since added to Test-excluded/Inaccessible, or now a non-testable type) instead of re-probing them every rerun. Returns NO_RUN / ALREADY_RUNNING / NO_ERRORS / RESTARTED.

Cancel test (cancel) — cancels the outer coroutine + every per-item job, marks anything still PENDING/RUNNING as FAIL "Cancelled" (cancelled items skip the increment hook, so they never pollute Blocked/Test-excluded), then flushes settings + persists the run.

Concurrency

There is no separate maxTestApiCalls setting in the current source. The sweep sizes its own local semaphore (ioCap) to GeneralSettings.maxConcurrentApiCalls (default 100) so it never binds tighter than the shared global cap — "no per-batch limit any more," per the engine's own comment.

  • Every item goes through the shared runThrottledBatch helper (the same one Fan Out / Fan-in / Fan Meta / workers use) in the canonical order ioCap → ApiCallCaps.global → per-host (ProviderThrottle). See Throttle — acquisition order.
  • Per-host caps come from ProviderThrottle — default 60 calls/min and 5 concurrent per host, per-provider overrides apply on top. See Throttle.
  • Permits are pre-acquired before each probe (permitPreAcquired) so the OkHttp interceptor doesn't double-acquire the same per-host semaphore and self-deadlock same-host probes; the L1 "Throttled" stat reflects items currently parked on that per-host gate.

L1 / L2 / L3 screens

The drill-in shape mirrors Fan Out's (stats panel + progress bar pattern reused). ModelTestScreen (ui/other/ModelTest.kt) owns a sealed ModelTestNav (L1 / Select / L2 / L3) with a rememberSaveable Saver + BackHandler, and auto-redirects a fresh entry with no persisted run straight to Select. ModelTestSelectScreen lists every testable provider with a checkbox (all pre-checked) and a per-provider model count; "Start test" launches the run scoped to the checked providers.

L1 — ModelTestL1Screen
  • Stats panel, two rows: the top row is the frozen catalog snapshot (Total / Inaccessible / Excluded / No chat / For testing / Costs); the bottom row is live progress (Done / Errors / Bench / Running / Throttled / Queued). "Errors" is the FAIL count minus benched items; "Bench" counts FAIL items currently on a >1h cooldown (reactive against ModelCooldownStore.cooldowns).
  • A progress bar shows while anything is queued or running, tracking (Done + Errors) / Total.
  • One row per provider, alphabetical by id, with a background fill showing that provider's tested fraction and a status icon (running, all-pass, all-fail, mixed-fail, queued). Tap opens L2.
  • Bottom buttons: idle → Test all models (opens Select) plus Rerun Errors (N) when the last run has errors; running → Check current test run + Cancel test.
  • The gear icon jumps straight to AI Setup → Test-excluded models; the 🐞 trace icon (when present) deep-links the trace list filtered to this run's runId.
L2 — ModelTestL2Screen

One provider's item rows, sorted running/queued → failed → passed, then alphabetically. Each row: status icon, model name, and cost (when non-zero); a footer row totals the provider's cost. The info icon opens the provider's own edit screen (not Model Info). Tapping a row opens L3.

L3 — ModelTestL3Screen

Single-model detail: status line (Passed / Failed / Running / Queued) with icon and colour, the error message when present, latency + cost, the fixed prompt, and the model's raw response text. The 🐞 trace icon (when a trace was captured) deep-links straight to that call's trace. Swipe left/right over the content steps to the next/previous sibling in the same provider-scoped order L2 shows — there's no separate chevron control.

Auto-feeds

The sweep automatically feeds three Settings lists from its outcomes — each user-editable under AI Setup → AI Models. Full mechanics (picker dimming, CRUD screens, prefs keys) live in Model states; this is the test-sweep-specific slice.

Blocked models (Settings.blockedModels)
Live, per item, as the run progresses (applyTestItemIncrement): PASS drops any existing entry for the pair; FAIL not on a cooldown upserts it with the error (truncated to 300 chars, default "Test failed"); FAIL on a cooldown drops it instead (the cooldown list owns that pair). Hand-curable with a reason text via the Blocked CRUD.
Test-excluded models (Settings.testExcludedModels)
Auto-added when a probe's totalCost exceeds COSTLY_PROBE_USD_THRESHOLD (5¢); the user can add or remove freely. Skipped by future sweeps but stays fully picker-visible. Seeded from assets/excluded.json on every cold start via TestExcludedSeed.
Inaccessible models (Settings.inaccessibleModels)
Tier-gated catalog entries the account can't actually call (Together non-serverless, SambaNova retired ids, generic 404s). Dims but stays selectable in every picker — distinct from Test-excluded, which is sweep-only. Auto-added on the tier-gating signals in Run lifecycle. Seeded from assets/inaccessible.json (64 bundled entries today) via InaccessibleSeed.

Seed asset files

Both assets/inaccessible.json and assets/excluded.json are delta-merged on every cold start — bundled entries whose (providerId, model) key isn't already in the user's list are appended; existing entries are never overwritten. So updating an asset reaches existing installs without destroying user edits.

To curate a new bundled entry: append the row to the asset JSON, push a build, the next cold start picks it up.
