# Startup fix and validation — 13 September 2026

## Result

The loading wait is substantially shorter on the populated debug emulator.
Measured from Android's activity START event to publication of `settingsReady`:

| Measurement | Before | After |
|---|---:|---:|
| Cold launch 1 | 28.541 s | 2.145 s |
| Cold launch 2 | 30.380 s | 2.548 s |
| First loading-screen frame, run 1 | 1.279 s | 0.733 s |
| First loading-screen frame, run 2 | 2.084 s | 0.474 s |
| Core preferences XML | 7,733,873 bytes | 438,563 bytes |
| Unchanged trace files parsed for cold listing | 5,451 | 0 |
| Current report bodies loaded for ledger check | 124, twice | 0 |

The final APK also reached settings-ready in 2.753 s while rebuilding a damaged
report index, and about 2.9 s while repairing one invalid trace-index entry.
Full pricing catalogs completed in the background; they no longer gate navigation.

These are settings-ready measurements, **not a fully-interactive benchmark**.
The emulator restarted between the before and final measurements. The same
retained dataset was verified, and the emulator still exposed one CPU and
2,018,744 kB total RAM, but OS scheduling/cache state was not controlled.
The first install/migration is slower; physical-device and release-build
performance were not measured. No fixed speedup is promised for every device.

## Changes

- Moved large provider catalogs into immutable, hashed files. Small references
  remain in preferences. Existing installations migrate their inline values
  once; writes publish the file before its reference, with an inline fallback
  when file storage fails.
- Kept raw model-list responses on disk during ordinary startup. Token-limit
  backfills now use streaming parsing and a revision marker, so unchanged
  catalogs are not reparsed on every launch.
- Added report-header and trace-metadata indexes. Source file identity, size,
  and nanosecond modification time invalidate changed entries. Current ledger
  headers skip full report decoding; pending-cost recovery remains mandatory.
- Deferred bulk pricing, trace warming, and broken-work scans until essential
  settings are ready. Broken-work disk scanning runs on IO. Derived model
  fields publish once and are reused until their inputs change.
- Kept saved/native/manual prices available during catalog loading. Manual
  override CRUD uses its own small-map lock and copy-on-write publication;
  background billing still resolves through the full catalogs. A thin progress
  indicator represents model-detail loading.
- Kept backups compatible: preference export expands catalog references to the
  original inline strings under the catalog-write lock. No backup version bump
  is required. This compatibility path was source-reviewed; a complete
  backup/restore cycle was not run.

## Validation and data preservation

- `:ai:assembleDebug` passed. Final APK installed with `adb install -r`, copied
  to the cloud APK path, launched, and manually inspected in the emulator.
- Repeated cold launches reused all 124 report headers and 5,451 trace entries.
- Damaged report-index input rebuilt all 124 headers; the following scan parsed
  zero source files. An invalid trace-index entry reparsed exactly one source
  file and recovered the full 5,451-entry list.
- All **5,604 protected files** were byte-identical against pre-change hashes:
  report JSON, chat history, trace evidence, and pricing preferences. No new
  provider calls were generated by the cold-start checks.
- All 169 catalog references resolved and matched their SHA-256 content hashes.
  Unreferenced revisions were pruned after preference flush.
- UI inspection confirmed all three manual overrides: Groq `gpt-oss-120b`
  0.15/0.60, Groq `gpt-oss-20b` 0.075/0.30, and OpenAI `gpt-5.4-mini`
  0.75/4.50, expressed in USD per million input/output tokens.
- 517 original preference keys matched their canonical pre-change hashes.
  Worker configuration, prompts and explicit model-type overrides were among
  the unchanged keys. All 20 parameter presets retained their values.

An intermediate build used a broad settings save after recomputation. This
materialized the existing Gson empty-list defaults in 18 capability maps and
19 parameter presets, refreshed 13 derived price/capability keys, and rewrote
four stored provider type caches (AtlasCloud, Glama, Requesty, Vercel AI Gateway).
The 18 capability maps and parameter presets were checked for semantic
equivalence. Exact original serialized values for the four type caches were
not recovered, so those are not claimed byte-identical; explicit user type
overrides were verified unchanged. The final implementation saves only derived
price/capability fields during snapshot maintenance and preserves extra stored
type entries during loading.

No unit/instrumented suite, app-data clear, uninstall, or complete snapshot /
restore was run for this default-cycle change. Remaining startup work includes
full pricing warmup and normal rendering/JIT activity; the first post-install
launch still logged a later frame-skip burst. Subsequent measured cold launches
and index-recovery runs did not log a frame-skip burst.
